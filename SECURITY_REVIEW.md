# Проверка безопасности MealPoint

Дата: 19 сентября 2026. Область: предоставленные исходники, зависимости, локально запущенные API и кабинет. Это не аудит инфраструктуры хостинга и не гарантия отсутствия всех возможных уязвимостей.

## Исправления

| Проблема | Исправление |
|---|---|
| Критическая: смена номера в профиле могла привязать чужие подписки и чаты без подтверждения номера | Удалено автоматическое присвоение данных по номеру; телефон используется только как контакт |
| Старые SMS-маршруты сохраняли альтернативный небезопасный путь входа | Отключены с ответом 410; вход клиента через подписанный Telegram Login |
| Telegram callback не был привязан к начатому в браузере входу | Добавлен случайный state в HttpOnly cookie, проверка state и запрет повторяющихся подписанных параметров |
| Часть изменений кабинета не имела проверки источника запроса | Добавлена проверка Origin относительно настроенного домена; в production без домена изменения отклоняются |
| Контакты и факт оплаты могли зависеть от запроса клиента | Контакты берутся из аккаунта, допустимые способы оплаты проверяет сервер, paid_at устанавливает менеджер |
| Повтор отправки формы мог создавать повторную подписку | Идентификатор оформления, уникальность на клиента и транзакционная блокировка |
| Самовывоз позволял хранить/менять время; неполная проверка дат и минут | Серверная проверка ISO-даты и диапазона 12:00–18:00, время только для DELIVERY; старые времена самовывоза очищаются схемой |
| QR требовал согласованной проверки состояния и повторного сканирования | Проверяются активность, принадлежность, точка, день; транзакции и уникальность предотвращают двойное списание |
| Устройство могло вызвать ошибку сравнения секрета нестандартными символами | Сравнивается длина байтов перед constant-time сравнением |
| Риск небезопасных вложений и доступа к чужим чекам | Ограничения размера/пикселей, проверка формата, декодирование и повторное кодирование в WebP, приватный маршрут выдачи |
| Гонки при создании чата | Создание разговора сериализуется блокировкой пользователя |
| Лишние внутренние поля подписки в ответе клиенту | Явный список возвращаемых полей |
| Уязвимые зависимости | Обновлены Next.js, React и связанные зависимости; npm audit сообщает 0 известных уязвимостей |
| Риск включения секретов/копий БД в образ | Добавлен .dockerignore; .env и резервные копии исключены |

Также добавлены ограничения частоты создания подписок и сообщений, защитные HTTP-заголовки и остановка камеры при закрытии сканера.

Официальная информация, использованная при обновлении Next.js: https://nextjs.org/blog/august-2026-security-release

## Проверки

- Production-сборка `npm run build` и проверка TypeScript завершились успешно.
- `npm audit --omit=dev --json`: 0 известных уязвимостей на дату проверки.
- 32 интеграционные проверки прошли через реальные HTTP-маршруты приложения с изолированной PostgreSQL-совместимой PGlite-базой. Схема применена дважды для проверки повторного запуска. pgcrypto extension не загружался в PGlite, где gen_random_uuid доступен встроенно; на рабочем PostgreSQL используется исходный CREATE EXTENSION.
- Проверены чужие подписки/расписания/изображения, запросы с чужого домена, подмена контактов, отсутствие самостоятельного подтверждения оплаты, повтор оформления, неверные даты/время, активация менеджером, неправильный и подделанный QR, запрет повторного списания, загрузка/нормализация изображения и отклонение SVG под видом картинки.
- В браузере: оформление, read-only контакты заказа, отсутствие времени самовывоза, банковские QR, формула 350 × 2,75, переход к чату и отправка изображения; реальный декодер QR считал сгенерированный QR точки из файла и выполнил списание. Ошибок в консоли при этих сценариях не обнаружено.

## Ограничения

- Производственная база и хостинг не были доступны. Миграция подготовлена, очистка рабочей базы и публикация не выполнялись. Скрипт очистки требует настоящего pg_dump; полное резервное копирование и восстановление на инфраструктуре владельца здесь не тестировались.
- Не выполнены реальный Telegram-вход с ботом владельца, банковский перевод, проверка камеры телефона и физического электронного замка.
- Статический QR точки можно сфотографировать и считывать вне точки: он не доказывает физическое присутствие. Подпись предотвращает подделку точки, но не копирование настоящего кода.
- Автоматического банковского эквайринга нет: используются предоставленные статические реквизиты и подтверждение менеджером.
- Ограничения сообщений снижают злоупотребление, но не заменяют общий лимит хранилища и резервное копирование базы. Вложения хранятся в PostgreSQL и увеличивают её размер.
